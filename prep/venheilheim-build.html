The words you'll need

Code is the written instructions a computer follows. It's kept as ordinary text files, and each file is called a script. This project has two separate kinds of code, written in two different languages, and the course keeps calling them by name:

Game code

The code inside the game. It runs on the phone or PC while someone plays: movement, combat, the story, dialogue, saves, menus.

Language: GDScript, Godot's own. Folder: game/. About 33,000 lines.

Example: player.gd decides what happens when you press dodge.

Tool code

Helper programs that run only on the development computer, before the game is built, to make the game's content. Players never run it and it isn't in the app.

Language: Python. Folder: tools/. About 21,000 lines.

Example: gen_world.py builds the whole island map; an importer cuts a generated sprite sheet into animation frames.

Think of a film: the game code is the film playing in the cinema, and the tool code is the studio equipment used to make it. The audience only ever sees what the equipment produced. Here, the tool code writes files (maps, sprites, sound loops) and the game code loads those files and brings them to life.

How the pieces connect

  1. You write a prompt: a written request for a picture, with exact sizes.you
  2. An image model (an AI that draws) turns it into a big sheet of drawings.image AI
  3. Tool code (Python) cuts that sheet into game-sized sprites, and other tool scripts generate the maps.tool code · run by Claude Code
  4. Godot, the game engine, imports those image and data files so the game can use them.the engine
  5. Game code (GDScript) uses them while the game runs: draws the map, moves Eirik, plays the story.game code · written by Claude Code under your direction
  6. An export (a build) packs everything into one app file: an APK for Android, an .exe for Windows.the engine
  7. adb copies the APK onto your phone, and you play it and judge it.you

Module 1

The project in one minute

After this you can

Give a 30-second and a 2-minute pitch, and quote the project's real numbers.

Venheilheim is a 2D top-down pixel-art action RPG with an open world, made in the Godot engine. It is built mobile-first for Android and also ships for Windows and Linux. Big story moments are told as comic panels; everything else is played.

The story: Eirik, the newly crowned Human King, marries Syra. Her dowry jewel, the Hollow Shard, was planted by Malakor, the Uren ruler. The Shard drains Eirik's Aura Core, explodes and kills Syra, and a golden rift pulls Eirik to the island of Venheilheim. There, powerless, he learns an older power called Ren, trains, builds a ship and sails north through a mist only Ren can see through. Act I ends with him wrecked and adrift as an Uren warship approaches.

What is built, in play order

  1. The opening in Lierdand Valley: a cliff city, a sparring lesson with Halvard that teaches Aura, Aura Slash and Aura Dash.
  2. The pirate assault: the march to the Wyvernwood, scouts, the camp, the stockade, the cove, the boss Red Mattock, hauling up the river chain.
  3. The way home: on horseback, Lierdand Harbour, a royal galley up the river, a barge to Solaris.
  4. Solaris and the Prologue: the capital, the homecoming crowd, the royal procession, the wedding, the Shard, the rift.
  5. Act I on Venheilheim: the ruins, the sword, the Training Grounds with four Ren circles and trials, the Cradle and the prophecy, building the ship.
  6. The sea crossing: mist, sea creatures fought from the deck, a storm, a giant monster, the wreck, the rescue ship.

Module 2

The engine: Godot and GDScript

After this you can

Explain why Godot was chosen, and its core ideas: nodes, scenes, scripts, autoloads, signals, renderer and screen scaling.

Godot (version 4.7.2 here) is a free, open-source game engine. Its own scripting language, GDScript, looks like Python and is built into the editor.

Why Godot, not Unity or Unreal

  • The project changed direction. The first plans were 3D, then Unreal Engine 5. They moved to Godot and 2D pixel art because the scope (a whole act of story) was only realistic in 2D, and the game had to run well on phones.
  • It's light and free. No licence fees. The development machine has no graphics card, and Godot's simpler renderer runs fine on it.
  • Strong 2D and easy exports. Godot has proper 2D tools (pixel-snapped sprites, tile maps, 2D physics) and exports to Android, Windows and Linux from one project.
  • Everything is text. Scenes, scripts and settings are plain text files, so scripts and an AI agent can read, write and diff them, and tests can run from the command line with no window (--headless).

The core ideas

  • Nodes and scenes. Everything is a tree of nodes: a sprite, a collision area, a timer, a camera. A scene is a saved tree you can reuse. Eirik is a node with a sprite, a body and hit areas under it.
  • Scripts attach behaviour to a node: player/player.gd handles movement and combat.
  • Autoloads are singletons loaded at start and reachable from anywhere. This project has five: Events (the signal bus), Game (input, settings, hit-stop, screen shake), StoryState (chapter, flags, abilities), SaveSystem and Quests.
  • Signals are Godot's events. Systems don't hold references to each other; they emit and listen through Events, for example player_hp_changed, which the HUD listens to. That keeps the systems loosely coupled.
  • Renderer. The project uses GL Compatibility, the OpenGL-based renderer for older and weaker devices. It works on cheap phones and on a machine without a GPU.
  • Pixel scaling. The game draws to a 426×240 screen and stretches it to the window (canvas_items stretch mode), so pixel art stays crisp at any size. Sprites are stored at twice that resolution ("texel 2") for finer detail at the same on-screen size.
  • Shaders are small GPU programs. world/water.gdshader animates rivers (flowing lanes and glints) and the harbour sea (rolling swells and broken crests).
Problem and fix

Everything drawn by a shader came out too dark. The shader re-read the texture itself (texture(TEXTURE, UV)), which skips Godot's colour conversion and tinting. Fix: start from COLOR, which already holds the correct pixel.

Pictures drawn in code showed as white boxes. A texture loaded inside a draw call and not kept anywhere was freed before the frame rendered. Fix: keep loaded textures in a cache dictionary.

The game renders to a fixed 426×240 viewport, and Godot stretches it to the window in canvas_items mode with nearest-neighbour filtering. Every sprite is stored at exactly twice that resolution and drawn at half scale, so it gains detail without changing size. Characters are all 28 game pixels tall, so the scale stays consistent everywhere.

The water and flash shaders made everything too dark, because they re-sampled the texture and skipped the colour conversion and tint that Godot had already applied. Using the incoming COLOR value fixed it. Another one: textures loaded during drawing were garbage-collected before the frame rendered and showed as white boxes, fixed by caching them.

Module 3

Game architecture

After this you can

Walk an interviewer from launching the app to playing a story beat, and explain how story progress and saves work.

Boot order

title.tscn (title screen, pick a save slot) → act_card.tscn (the act's title card) → main.tscn. main.gd assembles the game: the world, the player, the camera, HUD, touch controls, the dialogue box, the comic player, the story director, the pause menu, the journal and the tutorial. It also changes maps, sets lighting moods (normal, underground torchlight, the Cradle's twilight) and plays ambience.

The story is a state machine

  • Chapters. StoryState.CHAPTERS is an ordered list of 32 chapter names, such as ASSAULT_STOCKADE, PROLOGUE_WEDDING and ACT1_TRAINING_GROUNDS. Exactly one is current.
  • Flags record smaller facts: mattock_spared, relic_opened, hw_company_mounted.
  • Abilities are unlocked as quest rewards, so the player learns one mechanic at a time.
  • Story scripts. One script per part: opening.gd, assault.gd, homeward.gd, procession.gd, voyage.gd, plus story_director.gd, which receives story events and runs the matching scene.
  • The world follows the story. Objects on the map carry rules such as show_in, hide_in or if_flag, so the right people and props appear in each chapter without separate maps.

Quests and saves

  • Quests live in data (assets/story/quests.json): steps of kinds like read, rest, defeat, take, reach and event. The journal only ever shows what the player has learned, never future steps.
  • Saves are JSON files in the app's user folder, three slots. The game autosaves when the phone sends it to the background.
  • Rest snapshots. Resting at a shrine writes a second snapshot; dying returns you to it, with defeated enemies back on their feet.
  • Save versioning. Each save carries a version number. When Solaris grew its Outer Ward, positions in older saves were shifted on load, so old saves still work.
Problem and fix

"Save and return to title" did nothing. Story scenes lock input while they play. One scene never released the lock, and the pause menu refused to open while input was locked, so the save button was unreachable. Fix (0.64.2): the pause menu is blocked only while a comic plays, and returning to the title clears the input lock, unpauses and resets the time scale.

Module 4

The world: maps, chunks and the camera

After this you can

Explain how a map goes from a Python script to the screen, and how the game stays fast on a phone.

Maps are data, made by scripts

  • Two files per map. A Python generator (for example tools/world/gen_world.py for Solaris and the island) writes <map>_map.bin, one byte per tile saying what it is (grass, cobble, wall, water, stairs…), and <map>_meta.json, every placed object: buildings, props, NPCs with their lines, doors, triggers, entry points, region names, rooms.
  • Sizes. The island map is 600×690 tiles; Solaris is about 522×332 after the Outer Ward and River Gate were added; each tile is 16 game pixels.
  • A tile atlas (tiles.png, with a hi-res copy) holds every ground tile. The world picks variants with noise so ground doesn't repeat.

Drawing it fast: chunk streaming

world/world.gd cuts each map into 32×32-tile chunks and loads only the chunks around the player, unloading the rest. Each chunk lays its tiles, spawns its props and people, and adds flat ground details (shadows, debris) to a single decal layer to keep the number of nodes down. Solaris's crowd is capped at 80 active people at once.

Depth and the camera

  • Y-sorting. Props stand on their bottom-centre point and are drawn in order of their y position, so Eirik walks in front of a wall's base and behind its top.
  • Colliders. Each prop type has a collision box or radius in a table in world.gd. Grass never blocks; walls, trees, rocks and water do.
  • Shadows come from a height value per tile type, with light from the north-west.
  • Rooms. House interiors are built in empty space beside the map. The world flood-fills the map into separate areas, and the camera stays inside the area the player is in, so you never see the black void or another house's interior at the edge of the screen.
  • Travel. A trigger object (event: "travel") sends the player to another map's named entry point.
Problem and fix

Seven Solaris buildings were black inside, the gaol among them. Their rooms had been placed using an old map coordinate, so the door led to empty space. Fixing one calculation in the generator (x1 + INT) put all thirteen work rooms where their doors point. A test that walks out of every room now reports only one blocked room, the King's study.

The bride vanished from the chapel. NPCs that move between chapters were only listed in the chunk of their first position, so the chapel chunk didn't know she should be there. Fix: list each NPC in the chunk of every position it can have.

Module 5

Gameplay systems

After this you can

Explain the player controller, combat, the Aura and Ren mechanics, enemies and how the game guides the player without arrows.

The player and combat

  • Movement uses acceleration and friction, plus sprint, dodge, a Slash then Heavy combo, and guard with a timed parry.
  • Hitbox and hurtbox are two kinds of Godot Area2D (combat/hitbox.gd, hurtbox.gd). An attack switches its hitbox on for a few frames; anything with a hurtbox on the other team that overlaps receives the hit once per swing.
  • Game feel. A short freeze on impact ("hit-stop"), screen shake, flashes and squash make hits feel solid.

Two energy systems, one at a time

  • Aura (the opening): a stored Core powering Aura Slash and Aura Dash. Eirik loses it at the wedding.
  • Ren (Act I): no Core. In the Meridian View the player routes Ren with direction keys: hands, head, legs, back to the heart. Four training circles teach it in order: Circulation, Repetition, the Beam and the Sword, Swift Legs.
  • Progress. Five clean repetitions give one power point. Each point adds 8% strength but makes the flow faster and harder to time. Ren use builds Strain on the meridians; too much and he seizes up.
  • Upgrades. Rare runestones are spent in a 25-node skill tree in a teaching book.

Enemies and allies

Kata Sentinels and Ren constructs in the Training Grounds; pirates in the Wyvernwood, including bowmen on towers and ladders who can be hit from every side; the boss Red Mattock with a hook pull and a sweep; and allied soldiers who fight his crew so Eirik faces him alone.

Guidance without waypoints

A firm design rule: no quest arrows or map markers. Directions come from people in conversation ("north-east, past the mill"), signposts, and the Resonance Fragment, which only glows warmer or colder. The rejected alternative was a compass, judged "too direct". The journal only records what the player has heard or read.

Phones

On-screen touch controls, a sprint toggle that's meaningful on a phone, and a pause button.

Problem and fix

The bowman on the ladder couldn't be hit. Archers on towers stand drawn higher than their feet, so their hurtbox sat on the ground below them and slashes from the side or back missed. Fix: perched archers get an extra hurtbox covering their raised body, and a soldier's line hints that Aura Slash reaches them.

Show model answer

It's a deliberate design choice: the world should feel lived in, so people tell you the way, as they would. How did you balance the Ren progression?

Show model answer

Power is bounded and has a cost. Five clean repetitions earn a point worth 8% more strength, but each point also speeds up the flow you must time, so getting stronger demands more skill. Show model answer

Archers on towers were drawn raised, but their hurtbox stayed at their feet, so you could only hit them from the front. I added a second hurtbox at their raised height for perched enemies, so slashes from any side connect, and added a hint line about Aura Slash.

Python tooling

After this you can

Explain why the content is generated by scripts, which Python libraries were used and what each tool family does.

About 21,000 lines of Python in tools/ make the game's data and art. The game never runs Python; it only loads what the tools write.

LibraryWhat it isUsed for
Pillow (PIL)image reading, writing and resizingcutting sprite sheets, resizing with LANCZOS, drawing map overviews and minimaps

The tool families

  • tools/paths.py holds every project path in one place, so scripts run from any folder.
  • tools/world/ has the map generators (gen_world.py, gen_lierdand.py, gen_port.py, …), tile makers and map_render.py, which draws the overview maps the owner follows in docs/maps/.
  • tools/sprites/ has the importers that turn generated art into game sprites (Module 7) and helpers to look at a sheet before cutting it (blob_index.py, contact_sheet.py).
  • tools/comics/ holds the comic script and panel curation (Module 8); tools/audio/ holds the loop preparation (Module 9).

Why generate, not hand-place?

  • Reproducible: rerun a script and you get the same map.
  • Easy to change: widen a gate or move the gaol by editing one line.
  • Reviewable: the layout is code, so it can be diffed and versioned.
  • Natural at scale: 1,016 Solaris houses are packed by a sampler; trees use value noise so they never sit on a grid.

Rules can be enforced in code too. Props within 34 pixels of the procession route are cleared automatically, and NPCs found standing on it are printed as warnings.

Module 7

The art pipeline

After this you can

Describe the round trip from a written prompt to an animated sprite in the game, and the problems AI-generated art caused.

The round trip

  1. Write the prompt first. Each needed sheet gets a prompt in SPRITE_PROMPTS.md: the exact size in game pixels, the rows and frame counts, the views (front, back, side), drawn at 4× on flat magenta with nothing touching, and reference images to attach.
  2. Generate. The owner generates the sheet with an image model and saves it in art_sources/sprites/ under the name the prompt gives.
  3. Look at it. Before cutting, check which piece is which (blob_index.py numbers every piece).
  4. Import. A Python importer cuts and places every frame (below) and writes a PNG plus a JSON layout.
  5. Check in the game. Import into Godot, take screenshots, compare sizes, then mark the prompt as supplied.
Fill this in from memory: the project files don't record which image generator made the sprite sheets. Be ready to name the tool or tools you used, and why. Some comic work came from other AI sessions in Google's Antigravity (Gemini).

How an importer cuts a sheet

  • Key out the magenta background to transparency (chroma keying).
  • Find the rows: count solid pixels per line and split at the emptiest lines near each expected boundary, because figures sometimes touch from row to row.
  • Find the figures in a row the same way, by columns, then keep the largest connected piece plus anything within a few pixels of it (hair, a strap, the blade).
  • One scale per sheet, never per frame. It's set by the standing idle pose, so Eirik is 28 game pixels tall in every animation and outfit.
  • Place each frame with the feet on one ground line, centred on the body's mass so a blade swung out doesn't push him sideways. Resize with LANCZOS, then threshold the transparency for crisp pixel edges.
  • Write the layout: frame size, origin, texel: 2, and each animation's row, frame count, speed and looping. In the game, core/sprite_sheet.gd turns that into Godot animations and can merge extra sheets onto a character.

Rules that kept quality

  • Eirik's look is defined by the owner's sheets and is never reshaped by code. He is 28 px like everyone else, never bigger, never a chibi.
  • Every sprite at texel 2; art drawn by code gets a redraw prompt instead.
  • No faking. Never paste characters into comic panels to imitate new art; get real art or keep the old.
  • No roads in sprites: the game draws its own road tiles.
Problems and fixes (good interview stories)
  • Mixed outfits. A sheet asked for armed and empty-handed versions side by side; the model mixed them within rows. Fix: one version per sheet, every row one animation, all sheets generated in one session with the same reference attached, then one importer at one scale.
  • Rows that overlapped (blades and fallen bodies reaching into the next row) couldn't be cut, so that sheet was asked for again with clear spacing.
  • A sheet that didn't match its brief. The wedding-uniform sheet came back with 15 rows instead of 18, with no hit rows and no side slash. I mapped what was there and borrowed sensibly: "hit" plays the first two stagger frames of death, and the side slash uses the side heavy cut.
  • The wrong view. A front sprint came back turned three-quarters to the right, so only those two rows were regenerated, then scaled to match the back sprint.
  • Gates facing the wrong way. City gates came back facing the viewer when the wall runs north–south. The prompt was rewritten with a layout reference; when it still failed, the gaps were left open rather than shipping wrong art.
  • Fitting art to the map. The gaol's yard gate was scaled so the passage between its stone piers is exactly 48 game pixels, the three-tile opening in the wall, which puts the piers on the wall tiles themselves.

Answer first, then compare
Easy

Who made the art?

Show model answer

I art-directed it and generated it with image models. I wrote detailed prompts with exact in-game sizes and reference images, generated the sheets, then a Python pipeline cut them into game sprites. Name the generator you used. I made the visual rules myself: the hero's design, scale, outfits and no faked compositing.

Medium

How do you turn one big generated image into an animation?

Show model answer

Key out the magenta background; find the rows by splitting at the emptiest horizontal lines; find each figure by columns and connected components; scale the whole sheet once by the idle pose so the character is 28 pixels tall; place each frame with its feet on a shared ground line, centred on its mass; and write a PNG atlas with a JSON layout listing every animation's row, frame count and speed. The game builds animations from that JSON.

Medium

Why scale per sheet and not per frame?

Show model answer

Per-frame scaling would make a crouch the same height as standing, so the character would grow and shrink during animations. One scale per sheet, set by the standing pose, keeps real proportions: a crouch stays shorter and the size stays consistent between animations.

Hard

What are the limits of AI-generated art for games, from your experience?

Show model answer

Consistency and layout. The model drifts in proportions between separate requests, mixes variants that share a row, ignores row counts, draws the wrong view, lets limbs cross into neighbouring frames, and leaves pink fringes from the magenta. I countered with tight prompts, one version per sheet, references from the game itself, one session per character outfit, automatic cutting that tolerates touching figures, and asking again for only the broken rows.

Hard

A generated sheet is missing three rows. What do you do?

Show model answer

First map what's actually there; the wedding sheet came with 15 of 18 rows. Use every good row. For the gaps, borrow frames that look natural: the death's first stagger frames as a hit reaction, the side heavy cut as a side slash. Note it in the prompt file, and offer the owner a small prompt for just the missing rows. Never stretch or redraw the character in code.

Comics and the story

Explain how the comic scenes are produced and played, and how the story canon is managed.

  • The panels. The Prologue's big moments are 46 panels in seven scenes (the intro, the royal garden, the vows, the Shard awakening, its message, the bride's death, the rift), generated at 1920×1080 and kept in production_vault/ with face and costume benchmarks for continuity.

Module 9

Audio

After this you can

Explain where the sounds came from, how they were made to loop, and how Godot plays them by position.

  • Three ambience loops so far: the waterfall, wind on exposed peaks and storm rain, 588 KiB in total.
  • Sources and licences. CC0 (public domain) recordings from Freesound, through public mirrors. Every source's URL, author, licence and SHA-256 hash is recorded in art_sources/audio/SOURCES.json, and credits ship with the game.
  • Preparation. tools/audio/prepare_ambience.py (NumPy, SciPy, libsndfile) trims the long recordings, makes the falls mono, removes low rumble, overlaps the end into the start so the loop has no seam, and levels everything with headroom. It's repeatable and never overwrites the originals.
  • In the game. Godot audio buses for mixing; positional players (AudioStreamPlayer2D) at the waterfall so it gets louder as you approach, with the listener on the player; fades by place and weather; ambience ducks under dialogue; the volume is set in the pause menu and saved.

Checkpoint 9

Answer first, then compare
Easy

Where did the sound come from? Any licensing concerns?

Show model answer

CC0 recordings from Freesound. CC0 needs no attribution, but I still recorded each source's URL, author, licence and a SHA-256 hash, and ship a credits file. I didn't assume a whole website is one licence; each file is checked.

Medium

How do you make a recording loop seamlessly?

Show model answer

Trim to a steady section, filter out sub-bass rumble, then crossfade the end into the beginning so the wrap point matches, and level it with headroom. It's done by a script, so it's repeatable and the originals stay untouched.

Medium

How does positional audio work in Godot 2D?

Show model answer

An AudioStreamPlayer2D sits at the sound's place in the world, and a listener sits on the player. Volume and panning follow the distance and direction between them. Buses group sounds for mixing, so ambience can be ducked while someone speaks.

Module 10

Testing and quality

After this you can

Explain how a game like this is tested automatically, and why tests are kept focused.

  • Headless test scenes. 48 test scenes in game/tests/ run Godot with no window (godot --headless). Each sets up a chapter, drives the game and prints PASS or FAIL per check. For example test_assault runs 47 checks: the scouts talk, there are no mid-raid rests, Mattock is fought alone, the chain is hauled, the company mounts.
  • Simulated input. Tests send key and tap events with Input.parse_input_event. A dialogue line takes two taps, one to finish the typing and one to advance.
  • Play bots. tests/play_assault.gd plays a whole section by goals, like a player would.
  • Screenshot scenes. 54 scenes jump to places and save PNGs, which are then actually looked at. They need a real window, so the owner is told before one opens.
  • Focused, not everything. The owner's rule: test only the area that changed. The full suite runs only for major changes.
Problems and fixes

A crash only in release builds. A delayed tutorial call fired after its lesson had closed and read a missing entry. Debug builds survive such script errors; release builds crash. A debug export of a repro scene printed the error. Since then, test logs are always searched for SCRIPT ERROR.

One typing error broke every test. GDScript couldn't infer a variable's type in a loop over tweens, and a parse error stops the whole script. Explicit types fixed it, and the rule "give variables explicit types when the value is a Variant" went into the handoff.

Builds and delivery

  • Export presets in game/export_presets.cfg describe each platform. Builds run from the command line, for example godot --headless --export-debug "Android" ../build/venheilheim-debug.apk. Test files are excluded from exports.
  • Versioning. Every release bumps the version name (0.64.7), the Android version code (155) and the Windows file and product versions together, and adds a README change-log entry.

  • Android SDK and adb. The Android SDK provides adb, the tool that talks to a phone over USB: adb install --no-incremental -r. Incremental install once reported "Success" while writes had failed, so it's not trusted. aapt2 dump badging checks the APK's version and icon.
  • Git and GitHub. Source, art, prompts and documents are versioned; builds are not (they exceed GitHub's 100 MB file limit and are rebuilt anyway). Commits happen only when the owner asks.

What's in a map file?

A binary grid of one byte per tile for terrain, and a JSON file of every object (props, buildings, NPCs and their lines, doors, triggers, entries, regions, rooms) with conditions for chapters and flags.

How do NPCs know what to say?

Show model answer

Their lines are in the map data, optionally per chapter or per flag, and can be overridden by id in a per-map lines file. House residents come from a smalltalk file, one entry per door, so nobody repeats.

What does "texel 2" mean?

Show model answer

Every sprite is stored at twice the game's pixel resolution and drawn at half scale: the same size on screen, finer detail. Props are recorded in hires.json and loaded through one helper; character sheets carry "texel": 2 in their JSON.

5

How do you stop the camera showing the void around a room?

Show model answer

The world flood-fills the map into separate areas. The camera is clamped to the rectangle of the area the player stands in, and rooms are framed in black.

6

How did you make rivers look like they flow?

Show model answer

A canvas shader in world space. The map gives each river a flow direction; the shader streams bands and short glints along it in lanes moving at slightly different speeds. The harbour sea uses a separate branch with bent swells and broken white crests rolling toward the shore.

7

How does the boss fight keep allies out of the way?

Show model answer

Allies aren't allowed to target the boss. They're assigned to his crew, and more crew spawn while fewer than three remain, up to twelve, so the soldiers stay busy and Eirik fights Mattock alone. His hook no longer chains straight into a smash.

What's the riskiest technical decision you made?

Generating all maps in code instead of an editor. It depends on the generators staying correct, as the room-offset bug showed, but it made large changes cheap and let tests and overview maps verify every regeneration.
